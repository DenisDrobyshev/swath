# swath

[![ci](https://github.com/DenisDrobyshev/swath/actions/workflows/ci.yml/badge.svg)](https://github.com/DenisDrobyshev/swath/actions/workflows/ci.yml)
[![python](https://img.shields.io/badge/python-3.10%20%7C%203.11%20%7C%203.12-blue)](https://www.python.org/)
[![licence](https://img.shields.io/badge/licence-MIT-green)](LICENSE)

Семантическая сегментация аэро- и космоснимков: от сырого датасета до страницы, на
которую можно бросить GeoTIFF и получить маску, знающую своё место на Земле.

*Swath* — полоса захвата, участок поверхности под сенсором за один пролёт. Пакет
занимается тем, что происходит с этой полосой дальше: нарезкой, обучением,
прогоном по растрам, которые не влезают в видеопамять, и выдачей результата в
виде, который открывается в ГИС.

```
swath prepare loveda --raw data/raw --out data/loveda
swath train --data data/loveda --output runs/landcover
swath evaluate --checkpoint runs/landcover/best.pt --data data/loveda
swath serve --checkpoint runs/landcover/best.pt
```

---

## Состав

| | |
|---|---|
| **Модель** | Residual U-Net в одном читаемом файле на чистом PyTorch. Без предобученного энкодера, без библиотек сегментации, с любым числом каналов. |
| **Обучение** | AdamW, косинусное расписание с прогревом, смешанная точность, взвешенная кросс-энтропия плюс soft Dice, матрица ошибок по всему валидационному сплиту, отбор чекпоинта по mean IoU, возобновление. |
| **Инференс** | Скользящее окно с блендингом по приподнятому косинусу: границы тайлов не отпечатываются на результате. TTA, карта уверенности, сито от крапчатости. |
| **Геопривязка** | GeoTIFF на входе, GeoTIFF на выходе: та же система координат, тот же трансформ. Плюс полигоны в WGS84 и покрытие в квадратных метрах. |
| **Сервис** | FastAPI и одна страница: перетащили снимок, получили наложение, карту уверенности, легенду с покрытием и ссылки на маску, GeoTIFF и GeoJSON. |
| **Чекпоинты** | Самоописывающиеся. Веса, аргументы архитектуры, имена классов и палитра лежат вместе, поэтому для загрузки не нужно ничего, кроме файла. |

## Решения

**Энкодер не предобучен, и это выбор.** ResNet с ImageNet дал бы чуть больше на
RGB и намертво зафиксировал бы три канала. Данные ДЗЗ это не RGB: у Sentinel-2
тринадцать каналов, и здоровое поле от голого отличает ближний инфракрасный.
Модель, принимающая `in_channels` аргументом, здесь стоит дороже пары пунктов IoU.

**Окна смешиваются, а не сшиваются.** Пиксель у края тайла классифицируется без
половины контекста, то есть хуже. Разрезать растр, взять argmax каждого куска и
склеить обратно значит выстроить эти ошибки в сетку поверх карты. Перекрытие с
весом, спадающим к краю до нуля, отдаёт пиксель тому окну, которое видело вокруг
него больше всего. Эффект измерен в `tests/test_predict.py`: на модели, специально
ошибающейся в восьми пикселях от края, наивная нарезка портит 44% внутренней
области, блендинг — 0.3%.

**Метрики считаются по одной матрице ошибок на весь сплит.** Усреднять IoU по
батчам — распространённое сокращение, которое молча выставляет оценку классам,
которых в батче не было. На LoveDA это не косметика: дороги занимают 1.9% пикселей,
сельхозугодья 34%, и редкие классы отсутствуют в батче за батчем.

**Валидация в обучении идёт по кропам, публикуемые числа — нет.** Кропы дёшевы
настолько, чтобы гонять их через эпоху, и этого хватает для отбора чекпоинта. Но
кроп не то, что пришлёт пользователь, и он не задействует скользящее окно.
`swath evaluate` считает на целых тайлах тем же предиктором, что и сервис.

## Результаты

Обучено с нуля на обучающем сплите LoveDA. Оценено на всех 1669 валидационных
тайлах в полном разрешении 1024 пикселя, тем же предиктором, что стоит в сервисе.

| класс | IoU | F1 | IoU село | IoU город |
|---|---|---|---|---|
| фон | 0.455 | 0.626 | 0.500 | 0.345 |
| здания | 0.507 | 0.673 | 0.415 | 0.564 |
| дороги | 0.490 | 0.658 | 0.360 | 0.547 |
| вода | 0.476 | 0.645 | 0.406 | 0.595 |
| пустоши | 0.334 | 0.501 | 0.254 | 0.411 |
| лес | 0.374 | 0.545 | 0.252 | 0.471 |
| сельхоз | 0.426 | 0.598 | 0.464 | 0.364 |
| **среднее** | **0.438** | **0.607** | **0.379** | **0.471** |

![примеры предсказаний](docs/examples.png)

![кривые обучения](docs/training.png)

Общая точность 0.615, mean IoU **0.438** при 16.8 млн параметров. Тридцать эпох
заняли 2.1 часа на одной RTX 4060 Laptop с 8 ГБ.

Три вещи, которые стоит взвесить:

- **Энкодер не предобучен.** Опубликованные базовые решения на LoveDA берут
  backbone с ImageNet и дают 0.47–0.50 mIoU. Старт со случайных весов стоит
  точности и покупает модель, принимающую любое число каналов.
- **Валидационный сплит и выбрал чекпоинт, и выставил оценку.** У тестового сплита
  LoveDA нет публичных меток: это то, что позволяет бенчмарк, и тот же протокол у
  опубликованных решений. Число всё равно слегка оптимистичное.
- **Области расходятся.** Село даёт 0.379, город 0.471. Смотреть надо на разрыв, а
  не на среднее.

Конфигурация, история по эпохам и отчёт лежат в
[`docs/reference-run/`](docs/reference-run): числа можно проверить, а не принимать
на веру.

## Установка

```bash
pip install -e ".[geo,service]"
```

Тяжёлая зависимость одна: `torch`. Экстра `geo` добавляет rasterio, которым держится
геопривязка. Без неё пакет обучается, предсказывает и отдаёт PNG-маски, а выгрузка
в GeoTIFF и GeoJSON падает с внятной ошибкой. `service` добавляет FastAPI и uvicorn,
`dev` — pytest и ruff.

Под CUDA сначала ставится соответствующая сборка torch:

```bash
pip install torch --index-url https://download.pytorch.org/whl/cu124
```

## Данные

Корпус по умолчанию — [LoveDA](https://doi.org/10.5281/zenodo.5706578):
аэрофотосъёмка 0.3 м по трём китайским городам, тайлы 1024×1024, семь классов
земного покрова, разделение на сельскую и городскую области. Регистрация не нужна,
лицензия CC BY 4.0.

```bash
mkdir -p data/raw
curl -L -o data/raw/Train.zip https://zenodo.org/records/5706578/files/Train.zip
curl -L -o data/raw/Val.zip   https://zenodo.org/records/5706578/files/Val.zip
swath prepare loveda --raw data/raw --out data/loveda
```

Распаковывается 2522 обучающих и 1669 валидационных тайлов. В исходных масках `0`
означает отсутствие данных, `1…7` — классы. `swath.data.loveda` переводит их в
`0…6`, а «нет данных» отправляет в игнорируемую метку, которая исключается и из
потерь, и из метрик.

Классы сильно несбалансированы, ради этого и нужна взвешенная функция потерь.
Замерено по 400 обучающим тайлам:

| сельхоз | лес | фон | вода | пустоши | здания | дороги |
|---|---|---|---|---|---|---|
| 34.4% | 25.0% | 24.7% | 7.7% | 3.5% | 2.8% | 1.9% |

Чтобы добавить другой корпус, нужна одна функция, возвращающая список пар
`Sample(image, mask)`, и регистрация:

```python
from swath.data import Corpus, register

register(
    Corpus(
        name="inria",
        title="Inria aerial image labeling",
        default_task="buildings",
        splits=("train", "test"),
        discover=find_inria_tiles,  # (root, split) -> [Sample, ...]
    )
)
```

Дальше корпус принимают все команды: `swath train --dataset inria`,
`swath evaluate --dataset inria`. Что зарегистрировано, показывает `swath info`.

## Обучение

```bash
swath train \
  --data data/loveda --output runs/landcover \
  --epochs 30 --batch-size 6 --crop-size 512 \
  --base-channels 32 --depth 4 --learning-rate 6e-4
```

Запуск пишет `best.pt`, `last.pt`, `history.csv`, `metrics.txt` и ровно тот
`config.json`, с которым работал.

На видеокарте с 8 ГБ эта конфигурация даёт пик 5.7 ГиБ. `--base-channels 48`
требует меньшего батча или кропа 384. Выход за предел хуже, чем кажется: Windows
начнёт вытеснять память в системную, и тот же шаг займёт в сорок раз больше
времени.

## Оценка

```bash
swath evaluate --checkpoint runs/landcover/best.pt --data data/loveda --split Val
swath evaluate --checkpoint runs/landcover/best.pt --domain Rural   # по областям
```

Целые тайлы 1024 пикселя через скользящее окно, всё в одну матрицу ошибок. Печатает
таблицу по классам и пишет те же числа в JSON.

LoveDA держит сельскую и городскую области раздельно. Отдельный подсчёт по каждой
показывает характерную беду моделей земного покрова: выучить один тип ландшафта и
развалиться на другом. Усреднение её прячет.

## Предсказание

```bash
swath predict --checkpoint runs/landcover/best.pt \
              --input scene.tif --output predictions \
              --overlay --geojson --tta
```

Пишет `scene_mask.png`, а для геопривязанного входа ещё и `scene_mask.tif` в той же
системе координат. `--overlay` добавляет наложение, `--geojson` векторизует маску в
полигоны WGS84 с площадями. `--confidence` сохраняет вероятность победившего класса
отдельным полутоновым растром: самый быстрый способ увидеть, где модель угадывает,
а не решает. В `--input` можно передать и каталог.

`--sieve N` убирает предсказанные области меньше N пикселей. Любой попиксельный
классификатор оставляет крапчатость, и просеивание — стандартная чистка перед
векторизацией. По умолчанию выключено намеренно: сито, достаточное чтобы прибрать
карту земного покрова, сотрёт и одиночный сарай.

## Сервис

```bash
swath serve --checkpoint runs/landcover/best.pt --port 8000
```

Откройте `http://127.0.0.1:8000`. Бросьте снимок на страницу, выберите модель.
Наложение вернётся вместе с легендой, показывающей долю сцены под каждым классом, а
для геопривязанной загрузки ещё и в квадратных метрах. В `--checkpoint` можно
передать каталог или повторить флаг: тогда на странице появится выбор модели.

Четвёртая вкладка показывает карту уверенности. На земном покрове там проступают
границы классов и крыши в тени. Наложение собирается в браузере из маски и входного
снимка, поэтому ползунок прозрачности срабатывает мгновенно, а не гоняет модель
заново. На страницу уезжает версия, уменьшенная до 2048 пикселей по длинной стороне:
маска на 64 мегапикселя в base64 весит десятки мегабайт, которых не покажет ни один
экран. Ссылки на скачивание отдают полное разрешение.

| Метод | Путь | |
|---|---|---|
| `GET` | `/api/health` | версия, устройство, число моделей, доступна ли rasterio |
| `GET` | `/api/models` | загруженные чекпоинты с классами, палитрами и метриками |
| `POST` | `/api/segment` | multipart-загрузка; возвращает маску, карту уверенности, отрисовку входа, покрытие и ссылки |
| `GET` | `/api/result/{id}/mask.png` | только маска |
| `GET` | `/api/result/{id}/mask.tif` | геопривязанная маска, если во входе была система координат |
| `GET` | `/api/result/{id}/mask.geojson` | векторизованные полигоны в EPSG:4326 |

### Docker

```bash
docker build -t swath .
docker run -p 8000:8000 -v "$PWD/runs:/models" swath
```

Образ под CPU, отдаёт чекпоинты из `/models`. Путь берётся из `SWATH_CHECKPOINTS`:
на неё `swath serve` опирается, когда `--checkpoint` не задан, поэтому контейнеру
не нужны аргументы.

## Задачи

*Задача* держит всё, чем одна постановка сегментации отличается от другой: имена
классов, палитру, число каналов, нормировку. Модель, цикл обучения и сервис от
этого не меняются. `swath info` показывает зарегистрированные: `landcover`,
`buildings`, `roads`, `greenery`, `flood`.

```python
from swath.tasks import TASKS, Task

TASKS.register(
    Task(
        name="solar",
        title="Rooftop photovoltaics",
        description="Солнечные панели на крышах.",
        classes=("background", "panel"),
        palette=((255, 255, 255), (255, 140, 0)),
    )
)
```

Направьте на неё датасет и обучайте. Знать об этом остальному коду не нужно.

## Тесты

```bash
pytest -q                      # модульные и интеграционные
ruff check src tests scripts   # линтер
python scripts/smoke_test.py   # обучение, предсказание и сервис насквозь
```

Дымовой тест работает на синтетических тайлах, поэтому CI прогоняет весь путь на
каждом пуше, ничего не скачивая.
